# Playbooks

Thin domain sheets carrying what the universal method cannot know. The mechanism — when one is
summoned and freshness-checked, how one is researched and drafted, what travels back and what
does not — lives in one place: the **Domain playbooks** section of
`../AGENTBRIDGE-BUILD-DIRECTIVE.md`. Three facts live only here.

**Tags.** Every rule carries one. `researched` — drafted from studying real practitioners;
homework, not yet touched by this method's hands. `felt` — a run under this method executed it:
followed and it held, followed and it failed and was corrected, or earned outright as a new scar.
The tag records whose hands have held the rule, not who wrote it first, so a confirmation moves
`researched` to `felt` the same as a correction does. There is no third tag. Homework and scar
tissue are both valuable and never confused.

**The sources companion.** Beside each playbook, `<domain>.sources.md` — read at summon and at
research, never copied into a project. One entry per source that feeds a living rule:

    ## <source, named>
    - Route: <the way in that actually worked, exact enough to repeat — an address whose route
      is lost is a source lost>
    - Feeds: <rule sections, by number>
    - Taught: <one line>
    - Verified: <date — the run or pass that last walked the route>

An entry that feeds no living rule is deleted in the same commit that killed the rule. The
companion says which routes work now; git holds which ever did.

**The provenance line.** The top of every playbook states facts, never adjectives: its birth tag,
and the runs that have deployed it, each by name.
